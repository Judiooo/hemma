# Hemma

**Hemma** — self-hosted персональный домашний портал для управления локальными сервисами, закладками и мониторинга доступности сервисов из одного браузера.

Проект в первую очередь предназначен для доверенной локальной сети и может разворачиваться с помощью Docker.

**Документация:** [English](README.md) · [Русский](README.ru.md)

## Возможности

- Локальные сервисы и закладки в настраиваемом интерфейсе
- Создание, редактирование и удаление сервисов, закладок и категорий
- Избранное и сортировка карточек перетаскиванием
- Локальный поиск с выбором внешней поисковой системы
- Светлая и тёмная темы
- Пользовательские обои и фоновые изображения
- Виджеты даты, времени и погоды
- Погода через Open-Meteo — API-ключ не требуется
- Мониторинг HTTP/HTTPS, TCP и ICMP
- История доступности, задержки и сбоев
- Настраиваемый интервал и таймаут проверки
- Ручная повторная проверка сервиса
- Поддержка favicon и иконок сервисов
- Импорт и экспорт конфигурации в JSON
- Хранение данных в SQLite
- Адаптивный интерфейс для компьютеров, планшетов и мобильных устройств
- Развёртывание через Docker

## Быстрый запуск

### Из исходного кода

Клонируйте репозиторий:

```bash
git clone https://github.com/Judiooo/hemma.git
cd hemma
```

Запустите Hemma:

```bash
docker compose up -d --build
```

Откройте:

```text
http://<IP_СЕРВЕРА>:8000/
```

Например:

```text
http://192.168.1.11:8000/
```

Просмотр логов:

```bash
docker compose logs -f
```

Остановка Hemma:

```bash
docker compose down
```

### С использованием Docker image

Hemma можно запустить без клонирования исходного репозитория, используя готовый Docker image из GitHub Container Registry:

```text
ghcr.io/judiooo/hemma:latest
```

Создайте файл `docker-compose.yml`:

```yaml
services:
  hemma:
    image: ghcr.io/judiooo/hemma:latest
    container_name: hemma
    restart: unless-stopped
    ports:
      - "8000:3000"
    volumes:
      - hemma-data:/app/data
    environment:
      PORT: 3000
      DB_PATH: /app/data/app.db

volumes:
  hemma-data:
```

Запустите Hemma:

```bash
docker compose up -d
```

При таком способе исходный код Hemma скачивать или клонировать не требуется.

## Хранение данных

Hemma использует SQLite для постоянного хранения данных приложения.

База данных внутри контейнера находится здесь:

```text
/app/data/app.db
```

При запуске из исходного репозитория через Docker Compose каталог данных по умолчанию:

```text
./data
```

Загруженные пользователем фоновые изображения также хранятся в каталоге данных.

Для запуска с опубликованным Docker image рекомендуется использовать постоянный Docker volume `hemma-data`.

## Конфигурация

Внутри контейнера приложение работает на порту `3000`.

Стандартная конфигурация Docker Compose публикует его на порту `8000`:

```yaml
ports:
  - "8000:3000"
```

Чтобы использовать другой порт на сервере, измените левую часть:

```yaml
ports:
  - "8080:3000"
```

Переменные окружения:

```yaml
environment:
  PORT: 3000
  DB_PATH: /app/data/app.db
```

## Мониторинг доступности

Hemma поддерживает три метода проверки:

| Метод | Что проверяет |
|---|---|
| HTTP/HTTPS | Выполняет HTTP-запрос и измеряет время получения ответа |
| TCP | Измеряет время установки TCP-соединения |
| ICMP | Отправляет ICMP echo-запрос |

Задержка HTTP — это время получения HTTP-ответа. Это не то же самое, что ICMP ping.

Для локальных сервисов TCP-мониторинг удобен, когда нужно проверить доступность порта и возможность установить TCP-соединение.

## Запуск без Docker

Установите зависимости:

```bash
cd app
npm install
```

Запустите сервер:

```bash
DB_PATH=./data/app.db PORT=3000 node server.js
```

Откройте:

```text
http://localhost:3000/
```

Для Windows PowerShell:

```powershell
$env:DB_PATH="./data/app.db"
$env:PORT="3000"
node server.js
```

## Безопасность

Hemma в настоящее время не предоставляет встроенную аутентификацию пользователей.

Проект предназначен в первую очередь для использования внутри доверенной локальной сети.

Если необходимо предоставить доступ к Hemma за пределами доверенной LAN, рекомендуется разместить приложение за reverse proxy с аутентификацией или использовать VPN.

Не рекомендуется напрямую выставлять Hemma в публичный Интернет без продуманной системы аутентификации и контроля доступа.

## Резервное копирование

Hemma поддерживает экспорт и импорт конфигурации в JSON.

Для полного резервного копирования сохраните постоянный каталог `data` или Docker volume, поскольку в них находятся база SQLite и загруженные пользователем фоновые изображения.
